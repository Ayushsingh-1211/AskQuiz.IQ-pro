## 2. Architectural Trade-offs & Stack Philosophy

1. **PostgreSQL as Universal Queue and Vector DB vs. Redis + Pinecone**:
   - *Rationale*: A major goal is the **$0 operating cost**. Using PostgreSQL for relational tables, full-text search (`tsvector`), vector embeddings (`pgvector`), and task queuing (`SKIP LOCKED`) eliminates the need for separate Redis, RabbitMQ, and Pinecone clusters.
2. **Server-Side Range Streaming vs. Third-Party Video CDN**:
   - *Rationale*: Storing video files under `DATA_DIR` and serving them via HTTP 206 Partial Content range requests allows learners to scrub instantly through multi-gigabyte lectures with zero paid video infrastructure (e.g. Mux or Cloudflare Stream).
3. **Dual Retrieval Backend (Local Hybrid vs. Cloud FTS)**:
   - *Rationale*: SentenceTransformer and PyTorch require >400MB RAM. On Render's Free 512MB RAM tier, loading PyTorch causes an immediate Out-Of-Memory SIGKILL. Adding `EMBEDDING_BACKEND=fts` allows the backend to run on pure PostgreSQL full-text search within 100MB RAM, guaranteeing 100% cloud uptime.
